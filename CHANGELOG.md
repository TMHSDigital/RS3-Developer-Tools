# Changelog

All notable changes to RS3 Developer Tools will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added

- `rs3dev test [path]`: runs `tests/*.lua` and `spec/*.lua` outside the client. The stubs generator now also emits `fakes/rs3_api_fakes.lua`, a stand-in for every API table, class, enum, event and lookup table (calls recorded, typed defaults returned, events emittable), and `test-runtime/rs3_test.lua` adds the behaviour tests need: in-memory PersistentDB, a component tree with hooks, `T.load`/`T.reload`/`T.shutdown`, `T.press`, `T.emit`, `T.find`, `T.subscriptions` and assertions. Lua 5.4 runs in WebAssembly (wasmoon) with no install; `--lua <exe>` or `RS3_LUA` uses a native interpreter. Every example ships tests that CI runs on all three platforms; `rs3dev init` writes a starter `tests/main_test.lua`; new skill `add-tests`. `tests/` and `spec/` never reach the zip or `dev_plugins`

- Claude Code plugin: `.claude-plugin/plugin.json` exposes the four skills from `cursor-plugin/skills` and declares the `rs3-plugin` MCP server; `.claude-plugin/marketplace.json` makes the repository a marketplace, so `claude plugin marketplace add TMHSDigital/RS3-Developer-Tools` followed by `claude plugin install rs3-developer-tools@rs3-developer-tools` installs both into any project. The release workflow bumps its version with the Cursor manifest

- Pages site: `api/` is a client-side search over every stub symbol (name, kind, signature, documentation anchor, stub file) and `tools/` has a page for every `rs3dev` command (its `--help` output) and MCP tool (description, category, annotations), generated by `scripts/build-site-pages.mjs` at deploy time so they cannot drift; the template's navigation links to both

- Stubs: every type the docs reference without declaring is now resolved and `_unresolved.lua` is empty. `overrides.json` gains `classes` (opaque `RuntimeSprite`, `PluginAudioResource`), `derivedClasses` (`ui.TextDataConfig` and `ui.SpriteDataConfig` carry the fields of `ui.TextData` and `ui.SpriteData` minus the documented omissions, plus `new()`), `fieldTypes` (`audio.SoundInstance.isPaused`, `.id`, `ui.ModelCamera.transitionMaskSprite`), `renames` (`ui.RadioGroup:SetOptions`, `:HasOption` as the headings and examples say) and `memberAliases` (`AABB:AddPoint` beside `AddPosition`); `returnTypes` accepts several return values. `InvTypeProxy`, `VarPlayer` and `ui.LabelData` are aliases; `ui.ComboField.new` returns `ui.ComboField`. All 14 signature/table return mismatches now carry an explicit override with its reason. A test over the committed stubs fails if an `any` alias comes back without an override

- Preflight `placeholder-email` warning; `package` refuses placeholder addresses (`--allow-placeholder-email` for tests) and ships `plugin.json` without `$schema`
- `.luarc.json` library path written relative to the plugin folder; `RS3_STUBS_DIR` override
- `@tmhs/rs3-plugin-mcp` ships a dedicated `dist/bin.js` executable so the npm bin symlink starts the server on Linux and macOS; a spawn smoke test guards it
- `rs3dev init --prettyui` whitelists the dependency global in `.luarc.json` (`diagnostics.globals`) and guards the first use, so the scaffold passes the LuaLS check it ships with; CI runs that check on plain and `--prettyui` scaffolds

### Fixed

- `unresolved.md` no longer lists a heading that groups several signatures (`PersistentDB` `Get`, `Set`) as a name difference, nor a heading-only member that an `extraFields` override already supplies
- `scripts/luals-check.mjs` dropped the first LuaLS diagnostic when it shared a line with the progress output
- Preflight `sandbox-global` no longer fires on table constructor keys (`{ debug = false }`), goto labels or parameters; it now also reports `_G.os`, `_G["io"]` and `rawget(_G, "debug")`. An empty folder reports `manifest-missing` and `main-missing` only
- `DocsClient` aborts a fetch after `timeoutMs` (default 15 s), retries network errors, timeouts and 5xx once, and serves the cached copy when every attempt fails; `docs_get` and the stub crawl can no longer hang. Every workflow job has a `timeout-minutes`
- `require` validation reads calls from tokens (comments and strings no longer count), reports dotted names as `require-dotted` with the slash form to use, and points out an unloaded `init.lua`; `.luarc.json` now declares only `?.lua`, matching the documented client rule
- Preflight `url-outside-manifest` is an error only for a literal passed to `HTTPRequest`; a URL in help text or a log message is a warning. `chat-permission`, `http-permission` and `tracking-permission` skip chains rooted at a local of the file (`local Chat = {}`)
- `sync` and `watch` reject a `--root` or `RS3_DEV_PLUGINS_DIR` that does not exist or is not a `dev_plugins` folder (named so, or beside the client's `*.jcache` files) instead of creating it; `--create-root` opts in. The root itself is never created, a non-empty destination without a `plugin.json` is refused before pruning, paths are resolved through `realpath`, and `watch` runs syncs strictly one after another. The example MCP configs no longer hard-code a Windows `RS3_DEV_PLUGINS_DIR`
- `rs3dev watch --no-prune`; `package` writes to `dist/<plugin>-<version>.zip` under the current directory by default and the watcher ignores the same dev artefacts that `sync` and `package` exclude; `init` writes `urls` only from repeatable `--url name=https://host/` flags; `validate --strict` and `preflight --strict` fail on warnings
- `rs3dev doctor [path]` reports Node, the `dev_plugins` root and how it was chosen, the stubs folder and module count, the LuaLS binary, the plugin's `.luarc.json` library path and the docs cache, with a fix per missing item and exit code 1; `rs3dev cache path` and `rs3dev cache clear` expose the documentation cache
- Preflight lifecycle checks: `shutdown-missing` (error), `subscribe-without-unsubscribe` and `per-tick-scan` (warnings), `component-not-destroyed` (note), implemented in `lifecycle.ts` over the token stream of every Lua file
- Optional `rs3dev.json` (schema in `@tmhs/rs3-plugin-schema`): `preflight.ignore`, `preflight.maxLineLength`, `preflight.minCommentRatio`, `sync.root`, `sync.prune`, `package.outDir`; inline `-- rs3dev-ignore <code>` comments; `--ignore`, `--no-config` and `--format text|json|github|sarif` on `validate` and `preflight`; the MCP `guidelines_preflight` tool takes `ignore` and returns `suppressed`
- `docs_get` resolves `section` by anchor first, then heading, slices by recorded line offsets and returns a `DOCS_SECTION` error listing the anchors when a heading repeats; the page converter handles `dl`, nested lists, admonition titles and inline `code`
- MCP server: `instructions` in the initialise handshake (rules and AI policy), annotations on every tool, prompts `new_plugin`, `fix_preflight` and `prepare_submission`, resources `rs3://stubs/index.json`, `rs3://stubs/unresolved.md` and `rs3://stubs/modules/{id}`, a `docs_index` tool that builds a per-user full-text index so `docs_search` answers plain-word queries with page sections, and a `devplugins_sync` dry run that lists the files a real sync would copy and remove
- `index.json` records provenance from the server (`source.indexEtag`, `indexLastModified`, `pageCount`, `generatorVersion`, per-module `etag`), so an unchanged site still regenerates identically; `rs3dev stubs status` sends the recorded ETag back with one conditional request and reports current, changed, unknown or offline; `docs_search` returns `stubsVersion`
- `package`, `sync` and `watch` share one exclusion predicate that also drops OS and editor junk (`Thumbs.db`, `desktop.ini`, `*.bak`, `*.orig`, `*~`, `*.swp`, `*.psd`, `*.xcf`, `*.log`, `__tests__`, `spec`, `build`, `coverage`) and honours a gitignore-style `.rs3ignore`; `package` reports per-entry sizes (`--list`), warns above `--max-size` megabytes or when a README ships, and ends with the submission checklist; `package --verify <zip>` inspects any archive (root layout, manifest, `$schema`, placeholder address, dev artefacts, `require` targets)
- `rs3dev adopt [path]` (also `init <folder> --existing`) writes `.luarc.json` and the agent files into an existing plugin without touching its code; `rs3dev luarc [path]` refreshes `.luarc.json` and says which stubs location won; `--vendor` copies the stubs into `<plugin>/.rs3/stubs` so the file is portable; `validate` reports `luarc-stale` when the library path no longer resolves
- Weekly API change digest: `scripts/stubs-diff.mjs` diffs two `index.json` files by name and kind; `stubs-regenerate.yml` prepends the dated digest to `api-changes.md`, uses it as the commit body and posts it as an Announcements discussion
- macOS and Linux parity: README install blocks for winget, Homebrew and apt, a shell-neutral quick start, the client folders the detection scans per platform, `defaultClientRoots` takes the platform as a parameter and no longer throws when `os.userInfo()` has no passwd entry, and CI runs a macOS leg with the darwin-arm64 LuaLS build
- Repository metadata: description, homepage, topics, Pages with the Actions source, Discussions
- Monorepo tooling: one `vitest run` over the repository tests and every package (`vitest.config.ts` projects) with v8 coverage thresholds, Biome lint and format (`npm run lint`, `npm run format`) wired into CI, `noUnusedLocals` and `noUnusedParameters`, tests for `scripts/luals-check.mjs` parsing and `scripts/link-workspaces.mjs --copy` (new `--root` option), and the macOS CI leg
- `rs3dev init --template window|event|library|minimal` (also the MCP `plugin_scaffold` `template` input) and editor files beside the plugin (`.vscode/extensions.json`, `.vscode/settings.json`, `.gitignore`, `.rs3ignore`, `README.md`; `--no-editor-files` skips them); every template is validated and LuaLS-checked in CI
- Examples `wiki-prices` (optional `httpAccess`, `urls`, `Plugin.urls`, permission gate and change event), `settings-panel` (`hasSettingsIcon`, `Event.SettingsLayerReady`, a `ui.Check` stored per character) and `chat-logger` (optional `chatAccess`, `Event.ChatMessage` by `ChatType`, counts only); CI validates, preflights, LuaLS-checks and packages every example and checks the shipped manifest
- README: who it is for, a status line, a real preflight capture, the diagram below the quick start, a troubleshooting table and a short comparison
- `scripts/build-luals-addon.mjs` assembles the stubs in LuaLS addon layout (`library/`, `config.json`, `info.json`); each release attaches `rs3-client-api-luals-addon-<version>.zip` beside the stubs zip, and the README explains editor use without the CLI
- `scripts/pack-check.mjs` asserts what every workspace tarball ships (run in CI and before publishing); `release.yml` publishes to npm with provenance through trusted publishing once the repository variable `NPM_PUBLISH` is `true`
- The stub generator refuses to write (exit 2) when a crawl visits fewer than 50 pages or shrinks modules or symbols by more than 10 percent against the committed `index.json`, or when unresolved notes balloon; `--allow-shrink` overrides. `stubs-regenerate.yml` opens or updates a tracking issue and uploads the log instead of committing
- CI verifies the SHA-256 of the LuaLS archive before extracting it; jobs that can write (`stubs-regenerate.yml`, `release.yml`, `pages.yml`, `stale.yml`) pin GitHub actions to commit SHAs and read-only jobs check out with `persist-credentials: false`
- Weekly `audit.yml` runs `npm audit` over every dependency and `ci.yml` audits production dependencies on every push; Dependabot alerts and private vulnerability reporting are enabled on the repository
- Dev and runtime dependencies upgraded: vitest 5, zod 4 (the MCP SDK accepts `^3.25 || ^4`), commander 15, chokidar 6, `@types/node` 24 to match the CI Node range; TypeScript stays on 5.9 until the 7.0 compiler has been evaluated separately
- Stub generator regexes rewritten so whitespace is collapsed once and `<...>` groups are stripped in a single pass (clears the CodeQL polynomial-ReDoS and incomplete-sanitization alerts); output is byte-identical
- Stubs: an enum that shares its page class's name (`QuestType`) is emitted with a `Kind` suffix and the class's scalar self-typed field follows it; several signatures for one free function (`lerp`, `slerp`) become one definition with `@overload` lines; a class documented on several pages (`ui.ComponentCollection` on nine) is declared once on its own page and only re-opened for extra methods elsewhere; `PluginShutdown`, `PluginDependencyUpdate` and the aliases are indexed; `index.json` has one row per name and kind. Invariant tests run over the committed stubs

### Changed

- Releases are manual (`gh workflow run release.yml`); Dependabot, stale and label-sync automation removed

## [0.1.0] - 2026-10-21

### Added

- `@tmhs/rs3-stubs-generator`: deterministic crawler for developer.runescape.com emitting LuaLS `---@meta` stubs (signatures and `@see` links only) with an `unresolved.md` report
- `@tmhs/rs3-luals-stubs`: 87 generated stub modules, `index.json`, `luarc.template.json`
- `@tmhs/rs3-plugin-schema`: `plugin.json` JSON Schema (draft 2020-12) with editor settings sample
- `@tmhs/rs3-devtools-core`: manifest validation, preflight checks, scaffold, dev_plugins sync with lock retries, debounced watch, deterministic zip packaging, docs client with ETag cache
- `rs3dev` CLI: `init`, `validate`, `preflight`, `sync`, `watch`, `package`
- `@tmhs/rs3-plugin-mcp`: stdio MCP server with `docs_search`, `docs_get`, `api_lookup`, `manifest_validate`, `guidelines_preflight`, `plugin_scaffold`, `devplugins_sync`, `package_zip`
- Cursor rules (9) and Claude Code skills (4) for RS3 plugin development, installed by `rs3dev init`
- `examples/hello-counter` reference plugin checked by LuaLS in CI
- CI on windows-latest and ubuntu-latest, scheduled stub regeneration committing to `main`
